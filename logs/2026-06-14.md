## 重大发现:load-最优域 CB-连通(推翻 CB 轴封死)

**思路标签：** `global-cbsat-relabel`（新思路，待建页）

**背景：** 用户决定换架构「从根节点重构」,在四条根级分叉中 commit **全局联合求解器**——把 greedy→PP 整个范式换掉,用全局求解器(CP-SAT/ILP)把 load-最优当**硬约束**(MS/MM/CI/CT 锁在 BOUNDS 下界),在该可行域内以 CB 为唯一目标最小化。该路是唯一既跳出 sa-search-exhausted(它只封 local 搜索)、又不松 load(避 cb-mm-tradeoff)的范式。但它自带一个关键未知:**load-最优可行域到底 CB-连通吗?**——若 load 锁死后 CB 已无自由移动空间(CB-locked),任何架构都无解,几千行白写。

**证伪优先(先 probe 再建):** 不直接写 C++ solver,先做一个**决定性探针**回答关键未知。`scripts/cb_connectivity_probe.py`:取 base454 在 online_13 的 load-最优输出,对 CB 最重的 job 用 CP-SAT 求「锁 load 指标全不退、min CB」。约束编码(全部源自 baseline,保证其余 job 固定时全局指标不退):
- 每 `(leaf,port,phase)` 负载 ≤ r → CI 保持 0、MS 不退
- 每 `(leaf,port)` 本 job 的 max-phase 贡献 ≤ `min(maxmultic, max(baseline_multi, r)) − 其余 job 固定和` → MM(Maxmultic)、CT(Cbttskc)均不退,且允许用**新端口**(不锁死 baseline 端口选择,否则会假报 CB-locked)
- CB = 每源卡相邻 phase 端口集合 XOR 非空示性,目标 min

**结果(决定性):**
| 量 | 值 |
|----|----|
| online_13 baseline | score 65.29 / CB 8150 / total_flows 84619 / MS 1.00 / MM 6.00 / CI 0 |
| target job=25 baseline CB | 1129（m=7, 7046 flows, 1477 CB pairs）|
| CP-SAT 解 (120s, FEASIBLE) | **CB=525（−604，−54%）**，load 指标全程不退 |
| CP-SAT 下界 | **36**（job25 真 CB 最优可能低至 36 vs 1129）|

**结论:CB 轴重开。** load-最优可行域**可证 CB-连通,且 headroom 巨大**——仅 job25 一个 job 就能在不动任何 load 指标的前提下砍 54% CB(+0.036 分),整 case 50% CB cut ≈ **+0.24 分**,下界 36 暗示理论空间远不止。这**推翻了** [[cb-pincered-no-wall-gap]] / [[sa-search-exhausted]] 的「CB 已结构性耗尽」判定:那些墙对 **local 搜索 / load-neutral 重排**成立(局部够不到这个 basin),但**全局联合求解能到达,且差距极大**。CB 从来不是结构封死,是 local search 看不见这个盆地。

**关键边界澄清(为何不与既有 insight 矛盾):** sa-search-exhausted 封的是「local 邻域挪流」、port-relabel-collapses 封的是「load-neutral 纯重排」、mcf-cannot-express-cb 说的是「可分离边成本模型表达不了 CB」——三者都没否定「在 load-no-worse 硬约束下用**全局非可分离求解器**(CP-SAT,可表达集合 XOR)直接 min CB」。CP-SAT 恰好不是 flow 模型、不是 local 搜索、不是 load-neutral 重排,**绕开全部三墙**。

**下一步(架构落地的真问题):** probe 用的是离线 CP-SAT(120s,远超 7.4s 门控),不能直接进 solver。架构落地要解的是:如何在 7.4s 内逼近这个全局最优——候选 = (a) per-job CP-SAT 限时求解(job 独立,可并行/限时);(b) 把 CP-SAT 揭示的 basin 结构提炼成一个能在 C++ 里跑的大邻域/列生成启发式;(c) 仅对 CB 最重的少数 job 上 CP-SAT、其余走原 PP。runtime 是唯一拦路虎,但**方向已验证有真金**。

## runtime 探针:per-job 全 CP-SAT 不可上线(候选 (a) 否决,锁定 (b))

**思路标签：** `global-cbsat-relabel`（续上,runtime-feasibility 第二道探针）

**动作：** 给 `cb_connectivity_probe.py` 加 `CpSolverSolutionCallback`(记录每个改进 incumbent 的 `(elapsed, CB)`)+ `--sweep` 模式(一次长 solve 录 CB-vs-time 曲线,再读各 budget 下 best-so-far)。在 online_13 最重 job25(7046 flows / 1477 CB pairs)上录 30s 曲线,读 0.5/1/2/3/5/7/10/20/30s 各点。回答架构唯一拦路虎:**离线 −54% 里有多少能活到 7.4s 门控内?**

**结果(决定性,否决候选 (a)):**
| budget(s) | job25 CB | Δ vs baseline(1067) | %cut |
|-----------|----------|---------------------|------|
| ≤7.0 | 1067 | 0 | 0.0% |
| 10 | 1067 | 0 | 0.0% |
| 20 | 1004 | −63 | 5.9% |
| 30 | 754 | −313 | 29.3% |

- **第一个可行 incumbent 要到 7.95s 才出现**(已越 7.4s 门控),且它 CB=1286 **比 baseline 还差**。
- **第一次打败 baseline 在 18.45s**(CB=1059)。7.4s 内 CP-SAT **产不出任何可用解**。
- 这还只是 35 个 job 里的 **1 个**,而 7.4s 门控是**整 case** 的预算。

**结论:候选 (a)「per-job 限时 CP-SAT 直接上线」否决。** ~22.5 万个 boolean channeling 变量,光 model build + presolve 就吃光门控,search 还没开始。离线 headroom 是真的(存在性探针没错,轴是活的),但 **CP-SAT 本身不能当生产机制**。架构落地锁定候选 **(b):把 CP-SAT 发现的 relabel 结构提炼成 C++ 内可跑的启发式**(大邻域/列生成),不搬求解器。

**下一步真问题(开始建 (b) 前的廉价诊断):** 不盲设计启发式——先扩探针 dump CP-SAT 30s 赢解、与 baseline 逐 flow diff,刻画「它到底把哪些 flow 的端口从哪改到哪」的 relabel pattern(是否集中在少数卡/少数端口、是否有可在 C++ 复刻的贪心规律),用 pattern 反推可在门控内跑的机制。

> 注:两次 baseline 抓取 job25 CB 从 1129(120s 那轮)漂到 1067(本轮),total_CB 8150→8244——base454 用 `clock()` 时间门控,load-最优输出有 run-to-run 抖动。不影响结论(两轮都远超「7.4s 内 0% cut」的判定线)。

## relabel pattern 探针:CB 增益弥散在 ~470 卡(候选 (b) 偏难,但指向强化 PC)

**思路标签：** `global-cbsat-relabel`（续上,第三道探针——刻画 relabel 形态决定 (b) 可行性）

**动作：** 给探针加 `--dump-relabel`:解完 60s 后把 CP-SAT 赢解与 baseline 逐 flow diff,统计 (1) 多少 flow 改端口 (2) 改动在源卡间的集中度 (3) 逐卡 CB before/after。目的:回答候选 (b)「把 relabel 提炼成 C++ 启发式」是否可行——**集中(少数卡)=可行,弥散(几乎所有卡)=难**。

**结果(job25, 60s, CB 1154→729 −37%):**
| 指标 | 值 | 诚实解读 |
|------|----|---------|
| flow 改端口 | 6719/7046 (95.4%) | **被端口标签对称性放大**——CP-SAT 无理由保留 baseline 标签,自由 relabel,虚高 |
| 源卡 touched | 2719/2757 (98.6%) | 同上,对称性虚高 |
| **逐卡 CB 改善** | **472/2757 卡 (17%)** | **去伪信号**:真正贡献增益的卡 |
| 每卡降幅 | 多为 2→0、4→1(最大 4→1) | 每张卡是**小幅、局部**收敛,不是少数重卡 |

**结论:CB 增益弥散,但形态指向「强化 PC」而非「全新架构」。** 去掉端口对称性虚高后,真实信号 = **~470 张卡各降一点点**(17% 的卡,每卡 CB 2→0 这种)的累加,而非 5 张重卡。这否决了候选 (b) 里「定位少数热卡、贪心修」的廉价版本(没有少数热卡)。但每卡的改善是**对单卡相邻 phase 端口的局部收敛**——这正是现有 `run_port_consistency`(L1076, chain-aware per-card 收敛)在做的事,只是它贪心顺序跑到后面**没有空闲端口**就放弃了。所以真实差距更像「greedy PC 因 load 争用提前停,把 470 张卡的小收敛留在桌上」,而非「需要不可约的全局协调」。

**三道探针的合并结论(architecture bet 已变形):**
1. 存在性(120s): 轴**开**,headroom 巨大(job25 −54%,下界 36)。
2. runtime(sweep): full CP-SAT **7.4s 内 0% cut**,第一个可行解都要 7.95s → 候选 (a) per-job CP-SAT 上线**否决**。
3. relabel 形态(dump): 增益**弥散在 ~470 卡**,每卡小幅局部收敛 → 候选 (b) 廉价版(修少数热卡)**否决**;但形态 = 「PC 留在桌上的小收敛」,指向**在图内强化 `run_port_consistency` 的全局性/load-aware 端口争用解决**,而非另起一棵 CP-SAT 架构。

**待用户裁定的分叉(已超出「probe 验证」进入「押注新机制」):** 用户当初 commit 的「全局联合求解器」范式,经三道探针证明其「在线跑全局 solver」形态 runtime 死、廉价提炼也不成立。真正活的下一步收敛到一个**图内**假设:**greedy PC 因 load 争用提前停,留下 ~470 卡的小 CB 收敛**——若能让 PC 全局化/二次扫(给被占端口的卡第二次机会、或按 CB 收益重排 PC 处理顺序),可能在 7.4s 内吃到这部分增益。但这是一次**押注性机制开发**(非 probe),且与「换架构从根重构」的初衷已偏离(收敛回强化既有 PP 链的一环)。停在此处交还控制权:把三道探针证据摆出,请用户裁定走哪条——(i) 图内强化 PC(load-aware 二次收敛,最省、最贴现有代码);(ii) 重卡 only 的限时 reduced CP-SAT(只对 CB 最重几卡上精确求解,其余 PP);(iii) 维持「CB 轴 achievability-open 但 runtime-bound」结论,转攻别处。

## 第四、五道探针:per-card CD=0% + 耦合成 3 大 blob → CB 轴 runtime-bound 实锤(用户选「(i)(ii) 都要」后)

**思路标签：** `global-cbsat-relabel`（续上,用户「1和2我都要」→ 实测 (i)(ii) 共同的 per-card 子问题）

**背景:** 用户选「(i)(ii) 都要」。analysis subagent 读 solver 确认:CB 逐卡独立(`calc_phase_mask_cbt` L1068 只读单卡自身 mask),卡间**只**经 (leaf,port) 共享 load 耦合,`global_out/in` 在 PP 链后才写一次(L4112)→「锁其它卡不动、解单卡」**良定义**。`run_port_consistency`(L1076)确实 strand:每卡选一个 best target port,只 commit 过 load guard(L1131-1140)的 flow,被挡的留原端口、**同一轮不重试次优端口**;`run_port_consistency_perport_refine`(L1261)在 online_13 规模被 gate 关掉(L1262-1267)。→ (i)(ii) 归结为同一个子问题:**锁其它卡、单卡精确 CB-min**。两条路是它的启发式形 vs 精确形。

**第四道探针 — per-card 坐标下降(`--per-card-cd`):** 逐卡精确 CP-SAT(其它卡固定、残余 load cap = 全局 no-worse 包络减其它卡),按 CB 重→轻扫,多轮至不动点。
| 量 | 值 |
|----|----|
| 解的卡数 | 866 卡全 OPTIMAL,1.4ms/卡,infeasible=0 |
| 恢复增益 | **0%**——pass 1 即不动点,无任何单卡能独立改善 |

**结论(第四道):base454 已是 per-card 不动点。** 锁其它卡,**没有任何一张卡能单方面降自己的 CB**(load 包络内)。合理:base454 本就跑 `run_port_consistency` 贪心收敛每卡 → 当然是单卡局部最优。这**推翻我自己上一段「greedy 提前停留了 470 卡在桌上」的解读**:greedy 没「提前放弃」,是真没有单方向改善;那 ~54% joint 增益**全在卡间协同**(挪 A 腾出端口让 B 收敛),单卡子问题表达不了。→ **(i)(ii) 两条路都被证伪**(都是 one-card-at-a-time 机制,而 one-card-at-a-time 恢复 0%)。

**第五道探针 — 卡间耦合连通分量(`--coupling`):** 既然增益要卡一起动,问:协同需要多大的联合子问题?建图:两卡若共占一个**满载**(at-cap, 无残余)cell 则耦合,求连通分量。
| 量 | 值 |
|----|----|
| 满载 cell | 9741,2757/2757 卡全触及满载 cell |
| 连通分量 | total 324,nontrivial 18,**top3 = 830/803/784 卡** |
| top3 覆盖 | **2417/2757 卡(88%)、CB ~1015/1046** |
| 最大分量规模 | **2220 flows(占 job 32%)** |

**结论(第五道,实锤):耦合塌成 3 个 ~800 卡 / ~2200 flow 大 blob,非小簇。** cluster-joint 解一个这种 blob ≈ full-job CP-SAT 规模(已证 >18s 才打平 baseline)。更狠:7.4s 门控是**整 case 35 job 的**,job25 摊到 ~0.2s——2200-flow 的 CP-SAT 连 model build 都建不完,且这种 blob 有 3 个。→ **没有 gate-tractable 的 per-cluster 机制**。

**五道探针合并 = CB 轴 achievability-open 但 RUNTIME-BOUND(终态):**
1. 存在性(120s):轴开,job25 −54%,下界 36。
2. runtime sweep:full CP-SAT 7.4s 内 0% cut(第一个可行解 7.95s 且劣于 baseline)。→ 候选 (a) 否决。
3. relabel 形态:增益弥散 472/2757 卡。→ 候选 (b) 廉价版否决。
4. per-card CD:**0% 恢复**,base454 已是单卡不动点。→ 候选 **(i)(ii) 否决**(增益全在卡间协同)。
5. 耦合分量:协同塌成 **3 个 ~2200-flow 大 blob**,cluster-joint = full-job 规模。→ **无 gate-tractable per-cluster 机制**。

**终态结论:** CB 轴的金子(offline −54%,+0.2~0.24 分)**真实存在但拿不到**——任何能表达卡间协同的机制(joint / cluster-joint)都是 full-job CP-SAT 量级,越 7.4s 门控;任何能进门控的机制(单卡 / 贪心 PC)都已是不动点、恢复 0%。这是比「机制全撞墙」更硬的判定:不是没找到机制,是**可证 achievability-open 的盆地与 gate-tractable 机制集**在 online_13 这种 84k-flow 案例上**不相交**。CB 轴判 **runtime-bound sealed**(区别于 proven-optimal sealed:轴本身没到底,是门控够不到)。下一步**不再投 CB**,回 idea graph 按探索/利用挑别的 family(global_state 主线 actual-global-out 等),或等 calibrate/generate 卫星。`global-cbsat-relabel` 思路状态维持「部分有效(probe-validated 方向,但 runtime-bound,无 gate-tractable 落地)」。

### min-cost-flow-init(未出版本): 用户解锁 dormant 后经分析双重否决封死

**思路标签：** `min-cost-flow-init`（→ `wiki/ideas/min-cost-flow-init.md`；本轮由 dormant 经用户显式解锁 → 分析剪枝 → 封死）

**思路：** 接 6-13 图内枯竭判定。v489(cross_dest proposal)+v490(portfolio 起点)+time-tight(纯调参)+port-relabel(塌缩 neutral_swap)+MM(整数舍入幻影)+comparator(v393-397 穷尽)连续证伪后，图内 cheap/medium 全部到边界。唯一未执行的预授权方向 = `min-cost-flow-init`（expensive 档，被 [[portfolio-diversity-matters]] 高入度死墙预言剪掉的 dormant）。用户「1 我觉得行」显式解锁，要求实测而非盲信墙预言。按 direction.md expensive-arm gating（仅当所有 cheap/medium 试穿后才考虑）+ 用户授权，派 analysis 实测此方向是否真能绕过墙。设想：让全局 min-cost-flow（边成本编码 CB 目标）产出一个 greedy/portfolio 够不到的结构性更优起点，喂进下游 PP。

**分析结论（未实现即剪，双重否决）：**
1. **建模不可行（致命，比墙预言更强的根因）：** CB（Cbtphsc, scorer L124-131）= 对每张 source card、每对相邻 phase，若两 phase 端口**集合**非空且不相等则 +1。这是 (a) 集合对称差的示性函数（非线性、非负载求和），(b) 同卡多 flow 的**联合**函数（一个 flow 选端口的 CB 代价依赖同卡其他 flow 的分配）。MCF 边成本必须按边**可分离**且为流量**线性/凸求和**——与 CB 的 cross-phase 集合耦合根本不兼容。故 MCF 至多优化负载求和/峰值型目标（CI/CT/MS/MM），而这些轴在 submit_core 上**已全部封死**（BOUNDS：MS/CI 封死，MM 仅 bench_15 +0.25 残余）。MCF 给出的更优 basin 恰好落在已封死的负载轴，**触不到唯一开阔的 CB 轴**。
2. **起点被 PP 抹平（已证）：** 即便把 MCF 解当又一个 init 候选塞进 `TRY_STRATEGY`（L3522），本质是「又一个起点」——所有 init 候选共享同一条 PP 链（L3782+），撞 [[portfolio-diversity-matters]]。v490 刚再确认：针对性 CB 偏好 shuffle 起点对 p=32 CB case（online_8/online_10）纹丝不动。

**pipeline 实证（analysis 读 solver 给出）：** `solve_job()`（L3479）= portfolio init（L3544-3780，30+ greedy 变体经 `TRY_STRATEGY` 择优）→ 统一串行 PP 链（L3782+，`run_global_swap`→`run_mc_repair`→lowr rebuild→`run_port_consistency`→`run_relaxed/neutral/cross_dest_swap`）。所有 init 候选共享同一条 PP 链——这正是「初始解差异被 PP 抹平」的机制实证。

**风险预判（即便强行实现）：** 大 case 84k flows（online_13）MCF 在 7.0s/proj 门控下极易触发 time_tight、复刻 online_3 越 7.4s；若改 MCF 成本压 CB 会动端口总负载 → 踩 [[cb-mm-tradeoff]]（neutral_swap 当初被选正因只换端口标签不动负载）。

**结论：** 封死（分析剪枝，无版本）。新增硬结论 insight [[mcf-cannot-express-cb]]：flow-based / LP init 只能优化负载求和或峰值，无法表达 CB；结合 [[portfolio-diversity-matters]]，flow-based init 这一支双重封死。这是用户解锁后的诚实实测结果——不是盲信墙预言，而是发现了比墙更强的建模层根因。

**图内方向全枯竭（接 6-13 判定，至此含 expensive 档）：**
- cheap/medium：actual-global-out（两支挖透）、cross-dest-top3-mixed（proposal/邻域撞墙）、time-tight（纯调参）、port-relabel（塌缩 neutral_swap）、MM（整数舍入幻影）、comparator（v393-397 穷尽）全部到边界/撞墙。

### 文献搜索(用户授权): PP 后 load-neutral CB 削减机制 → 证伪，空白不存在

**动作：** 把 CB 抽象成「相邻 phase 端口集合对称差最小化 = inter-slot reconfiguration churn over a phase chain」,搜文献(cf. *Costly Circuits, Submodular Schedules* arXiv:1512.01271、*Controlling Flow Reconfigurations in SDN*、stable-matching flow scheduling)。文献指向一个候选机制 = **全局链求解**(DP over phases / submodular),理论上能到达 local pairwise swap 够不到的构型 → 设想其绕过 sa-search-exhausted(只封 local 邻域搜索)且保持 load-neutral(只在 load 等价类内重排端口标签 → 避 cb-mm-tradeoff)。派 analysis 核三件事(是否已实现/是否可解/是否真 load-neutral)。

**证伪结论（三重塌缩，无版本）：**
1. **不新颖——已是主线：** `run_port_consistency`(L1076) 已是 **chain-aware**——`calc_phase_mask_cbt`(L1068) 对整条 phase 链联合评分,逐 card 把流向单一 target port 收敛。这正是已实现的主线 insight `score-aware-pc-chain`(v122→v163,+3 线上)。文献设想的「全局链一致性」基本已内建,缺的只是「逐 phase 自由端口分配 DP」。
2. **不可解：** 逐 phase 自由端口集合 DP 状态 = 2^p≤2^32 爆炸;唯一自然降维(state=card 流映射到哪个 port)恰好塌缩成 `run_port_consistency` 已贪心做的 single-target 收敛。m≤31 链长不是瓶颈,per-phase state 才是。无任何 load-neutral 的可解精确 DP。
3. **不可能 load-neutral（v491 已证）：** [[port-relabel-collapses-to-neutral-swap]]——跨 phase 同一置换对 Cbtphsc 集合判定不变(恒 0 收益);任何**真改变** CB 的端口置换必然改某 phase 的 per-port 负载,即必然是一次流移动,塌缩进 `run_neutral_swap`(L1504),而该 operator「属 sa-search-exhausted 墙的搜索范式」。

**双墙夹击无缝隙：** load-neutral 版 → 塌缩 neutral_swap，落在 [[sa-search-exhausted]] **内**；load-changing 版 → 撞 [[cb-mm-tradeoff]]（`40/Maxmultir` 权重 ≫ `5*Cbtphsc/TotalFlows`，换轴净负）。两墙之间**没有空白**。叠加运行时：online_13(84k flows)`allow_extra_pc_chain` 已被 gate 关掉，加全局逐 phase 求解必越 7.4s。

**元结论（本段 /goal 收敛）：** 文献开口已闭。「PP 后 load-neutral 降 CB 的全新机制」不是「未找到」而是「可证不存在」——CB 的非可分离 cross-phase 集合耦合本性([[mcf-cannot-express-cb]]) + 任何改 CB 必动 load(v491) 共同焊死了这条缝。本地图 + 文献空白**双重耗尽**。真正的下一步需要用户给一个**跳出当前问题抽象**的方向(如改目标函数口径理解、换 solver 架构、或质疑 CB 是否真是线上瓶颈),而非在已证封死的 CB 削减范式内再凑版本。
