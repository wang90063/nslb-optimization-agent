## 详细记录

### v489: cross_dest overflow-aware 候选端口排序

**思路标签：** `cross-dest-top3-mixed`（→ `wiki/ideas/cross-dest-top3-mixed.md`；本轮为该 ◐部分有效主线下的一个失败变体）

**思路：** global_state「换真实值」轴在 v454 后已结构性耗尽（analysis 约束事实 + v487 日志双重确认：`global_out += mo` 已精确匹配 scorer 的 sum-of-peaks 口径，pre_ct_mo 已成死代码；v472 续走该轴失败）。按 idea_graph 富图，CB（Cbtphsc）是 BOUNDS 唯一活轴，但 CB 的搜索挪流撞 [[sa-search-exhausted]]、松上限撞 [[cb-mm-tradeoff]]、动 global 传播撞 [[global-state-propagation]] —— 三墙合围。唯一穿过三墙的活口 = `cross-dest-top3-mixed`（load-safe operator，硬上限检查全程保留→避 cb-mm；不挪流搜索→避 sa-search-exhausted；不动 global 更新→避 global-state-propagation），且 ◐部分有效、cross_dest family n=6 未挖透，符合 exploit。

具体缺陷假设：`run_cross_dest_swap` 候选目标端口 top-k 排序用 `score = cnt*256 - joint_price_bias(...)`，纯按卡集中度 cnt 挑 top-3，不看该端口是否会撞 `cd_max_out`/`cd_max_in` 硬上限。结果一个高 cnt 但必然溢出的端口会占据稀缺的 top-3 名额（p=32 时 cand_limit=3），在内层 overflow 检查被否掉，白白挤掉一个可行的较低 cnt 端口 → proposal 命中率结构性损耗。

**实现：** `run_cross_dest_swap(int m)` 两处对称打分循环（双流段 + 单流段），打分前用流的 phase mask 位遍历统计溢出 phase 数 `ovf`（out/in 各自 +1），score 改为 `cnt*256 - joint_price_bias(...) - ovf*CD_OVF_BIG`，`CD_OVF_BIG=1<<20`（ovf≤2m≤62，ovf*BIG 峰值 ≈65M ≪ INT_MAX；cnt*256≤31744 ≪ BIG，任一溢出 phase 即把端口压到所有可行端口之下，溢出端口仅在可行端口不足 cand_limit 时递补）。内层硬上限检查、cand_limit、global 更新全部原样未动；对所有 case 一视同仁，无 case-level gate。

**结果：**

|--------|---:|---:|------:|
| submit_core | 901.68 | 901.17 | −0.51 |
| submit_anchor | 267.39 | 266.34 | −1.05 |
| contrast | 826.94 | 826.82 | −0.12 |
| prefport_veto | 389.19 | 389.28 | +0.09 |
| guardrail | 413.45 | 413.52 | +0.07 |
| candidate | 455.12 | 455.23 | +0.11 |
| transfer_holdout | 583.23 | 583.69 | +0.46 |

逐 case：submit_core 净 −0.51 **方向一致非散噪**——proxy 家族 6/9 集体下滑（proxy_1 −0.16、proxy_3/5 −0.06、proxy_7/8/9 −0.03）+ online_14 −0.12 + online_19 −0.06，仅 bench_15 +0.04。candidate +0.11 由 online_8 +0.18 单点拉动。transfer_holdout +0.46 由 lowr_4 +0.32 单 case 拉动。anchor 与 core 同向下行（param_p32_r4_n40 −0.68 主导），非独涨故不构成 anchor 红灯，只确认候选整体偏弱。

运行时：候选**新增 3 个 >7.4s 越线**——guardrail/hard_19 8.123s（基线 7.015s，+1.1s 从线下越到线上）、guardrail/hard_24 8.011s（基线 7.609s 已越，候选更慢）、anchor/medium_25 7.614s（基线 7.088s，+0.5s 越线）。overflow 探测的 per-candidate 开销把这些 case 推过线。

**结论：** 废弃。双重硬否决：(1) submit_core −0.51 方向一致真实回归（core 跌 → 红绿灯不提交，core 负信号优先于 candidate +0.11）；(2) guardrail 新增 hard_19 8.123s 越线（+1.1s，违反性能门控）。

死因（有价值的反向结论）：overflow 降权这个**看似合理的 proposal 质量改进实际有害**。把"必然溢出"的高 cnt 端口从 top-3 挤掉，反而让 cross_dest 错过一类有效交换——那些"单看会溢出"的端口在**双流交换**里仍是有用支点，因为配对的另一流会释放空间，单端口 overflow 预判会误杀这类配对机会。proposal 排序里用单端口静态 overflow 预判，与双流交换的动态可行性语义不匹配。cross_dest 的"加 overflow 感知降权"这条子方向封死。

### v490: CB-aware portfolio shuffle 重启（net-zero 起点多样性）

**思路标签：** `greedy-cb-awareness`（→ `wiki/ideas/greedy-cb-awareness.md`；本轮探索 actual-global-out 主线第 2 支 = CB-aware greedy portfolio 的未挖透变体，最终把这一支封死）

**思路：** 接 v489 同一 CB 轴（BOUNDS 唯一活轴）。v489 在 cross_dest operator 的 proposal 排序上失败后，转攻 `actual-global-out` 主线的**第 2 支**——CB-aware greedy portfolio（v447 引入，在 portfolio 层提供 CB 多样性而非在 better_metrics 注入 CB）。analysis 给的两个 portfolio hook（加 cb_w/local_w 组合）被 [[magic-number-leaves-fragile]]（参数微调）+ [[portfolio-diversity-matters]]（单变体起点被 PP 抹平）两墙夹击剪掉；距离衰减 hook 滑向 [[sa-search-exhausted]] 剪掉。唯一不撞墙的切口：portfolio-diversity 墙禁「砍 portfolio / 指望单变体更优」但**不禁增加起点多样性**。核实 scorer（L124-131：Cbtphsc 罚同卡相邻 phase 端口集合不同）确认 cb_bonus 方向正确。当前 4 个 cb_aware 调用 3 forward + 1 reverse，无一用 shuffle 重启（rev≥2，代码已支持）。设想：把 1 个 forward 调用改 shuffle 重启注入 CB 偏好的起点顺序多样性。

**实现：** net-zero 单参数改动——第 1 个 cb_aware 调用 `run_greedy_cb_aware(m,2,1,3,1)` → `(m,2,1,3,1,2)`（末尾 rev 0→2 启用 Fisher-Yates 洗牌，函数体洗牌逻辑已存在）。portfolio 候选数不变（仍 4 个），只是第 1 个起点顺序从 forward 变 shuffle。不动函数体/better_metrics/择优判据，无 case-level gate。fl_order 在调用前处于干净恒等态（L3501 初始化，到调用点之间无 rev≥2 洗牌），无脏序、无下游污染。

**结果：**

|--------|---:|---:|------:|
| submit_core | 901.80 | 901.56 | −0.24 |
| submit_anchor | 266.54 | 266.72 | +0.18 |
| contrast | 827.05 | 826.97 | −0.08 |
| prefport_veto | 389.19 | 389.18 | −0.01 |
| guardrail | 413.60 | 414.08 | +0.48 |
| candidate | 455.28 | 455.25 | −0.03 |
| transfer_holdout | 583.26 | 583.22 | −0.04 |

逐 case：submit_core 唯一真 mover 是 online_13 −0.27，其余 ±0.01 散噪。**预期利好的 p=32 CB case（online_8 +0.01 / online_10 −0.03）完全没兑现，纹丝不动。** guardrail 的 v489 越线 spike 消失（hard_19 8.123s→6.934s、hard_24 7.416s，net-zero 改动不增 cycle 兑现）。但 candidate/online_3 **8.769s（基线 7.930s，+0.84s）越 7.4s 线**——shuffle 重启在这个 p32-ish case 上加了 0.84s。

**结论：** 废弃。core −0.24（online_13 退 0.27）+ candidate 预期利好未兑现（持平）→ core 跌 + candidate 平 = 红绿灯不提交。叠加 candidate/online_3 越 7.4s 线。

死因（比 v489 更深的反向结论，封死整支）：shuffle 重启的 CB-aware 起点**对 p=32 CB case 毫无作用**（online_8/online_10 纹丝不动），印证 [[portfolio-diversity-matters]] 硬结论——**起点多样性已被 post-processing 抹平，再加一个 CB 偏好起点无法穿透 PP 影响最终解**。CB-aware greedy portfolio 这一支（actual-global-out 第 2 支）已挖透，封死。

**两轮（v489+v490）合并的元结论：** CB 轴上的局部改进——无论改 operator proposal（v489 cross_dest）还是改 portfolio 起点（v490 cb_aware shuffle）——都被 PP 抹平或撞 MM（[[cb-mm-tradeoff]]）。CB 轴的"构造/proposal 局部质量"路线已系统性穷尽；要再动 CB 必须换到 PP **之后**起作用、且不抬 MM 的全新机制层，否则就是在 PP 抹平区里打转。这是比单版死因更高一层的方向判断，应反映到下一轮选址。

### v491(未出版本): time-tight 方向经分析后剪掉 + 图内 solver 方向枯竭判定

**思路标签：** `time-tight-threshold-relax`（→ `wiki/ideas/time-tight-threshold-relax.md`；本轮分析后剪掉，未产版本）

**思路：** CB 局部质量轴(v489)+ portfolio 起点(v490)连续穷尽后，按 idea_graph 转向唯一未碰的 ◐部分有效 cheap 活 idea = time-tight-threshold-relax（pipeline，机制不在 CB 局部轴上）。设想：优化时间门控让被砍 operator 在更多 case 完整跑，吃回被砍 case 的 CB/CT 收益。

**分析结论（未实现即剪）：** analysis 诚实判定此方向 95% 是纯调参——(1) 当前门控 `proj = elapsed/jobs_done * total_jobs`（solveJob L3507-3510）**已是规模自适应外推**，我设想的「换结构判据」基本已内建，唯一可动的是 7.0 这个常数 + 二元粒度；(2) 纯调 7.0 阈值 = 撞 [[magic-number-leaves-fragile]]（v430 relax70 已封死，+0.04 边际几近耗尽）；(3) 唯一勉强算结构性的变体 = 门控粒度细化（proj∈[7.0,7.4) 时逐档解锁 S4/S5/S6 而非全砍 L3562），但收益全在 candidate p=32（理论+0.13）、需在 7.4s 内塞额外 CB operator，与 timeout 直接对冲——而 v489（hard_19 8.12s）+ v490（online_3 8.77s）刚两次证明 runtime 余量耗尽。期望值 = 高否决风险换微弱 candidate 收益，按 direction.md ③ 死墙剪枝剪掉。

**图内 solver 提分方向枯竭判定：** 至此本地图内所有 solver 提分方向已耗尽——
- 活 idea：actual-global-out（两支均挖透）、cross-dest-top3-mixed（proposal/宽度邻域撞墙）、time-tight-threshold-relax（纯调参）全部到边界或撞墙
- dormant：min-cost-flow-init ⚠撞 portfolio-diversity-matters、swap-iter-count ⚠撞 sa-search-exhausted（均被预言，剪）；calibrate-candidate-set 是校准动作非 solver 提分（且校准未到 3/3）
- 区分度正常（v489 −0.51/v490 −0.24/v487 −0.11 彼此分得开、逐 case 方向明确），非数据集分辨率问题，generate-dataset 逃生阀不触发

**元结论收敛的文献空白：** v489+v490 两轮锁定——CB 轴的「PP 之前/之中」局部改进全被 PP 抹平或撞 MM。唯一未被本地图覆盖的方向 = 在 **post-processing 之后**、**不抬 max-load（避 cb-mm-tradeoff）** 前提下降相邻 phase 端口冲突(Cbtphsc)的全新机制。按 direction.md「图内全枯竭→搜文献」，下一步转文献搜索此空白，而非在已穷尽轴上硬凑版本。
